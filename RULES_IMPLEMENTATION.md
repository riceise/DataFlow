# Персональные наборы правил — фактическое состояние

## Реализовано

- ASP.NET Core Identity, cookie-вход, antiforgery, владение источниками и проверки доступа к заданиям/строкам/retry/cancel.
- Наборы `RuleSet`, неизменяемые версии `RuleSetVersion` и документы `RuleDocument` в JSONB. Канонизация и SHA-256 для дедупликации.
- Создание и список наборов; изменение имени, описания и архивного состояния через `PATCH /api/v1/rule-sets/{id}` с `revision`.
- Создание/список версий, чтение и экспорт определения, независимая копия (`fork`).
- Прямой доступ по email, отзыв по UserId, публикация конкретной версии, каталог и библиотека закладок. Закладка не даёт права доступа.
- `Tabular`: произвольные колонки, mapping заголовков, типы и ограничения, результат `Valid`/`Invalid`. `Customer` сохраняет upsert.
- Выбор версии при upload, её закрепление в задании, fingerprint с версией и повторное использование задания для идентичного файла/версии.
- `Ui/`, маршрут `/rules`: вход, JSON-редактор/импорт, наборы/версии, публикация, выдача доступа, fork и CSV-проверка с polling.
- Backfill текущих и исторических схем: `tools/DataFlow.BackfillTool`, инструкция в [docs/rules-backfill.md](docs/rules-backfill.md).

## Фактические маршруты

Префикс `/api/v1`:

```text
GET/POST    /rule-sets
PATCH       /rule-sets/{id}
GET/POST    /rule-sets/{id}/versions
GET         /rule-set-versions/{id}
GET         /rule-set-versions/{id}/export
POST        /rule-set-versions/{id}/fork
POST        /rule-set-versions/{id}/grants
DELETE      /rule-set-versions/{id}/grants/{userId}
PUT/DELETE  /rule-set-versions/{id}/publication
GET         /rule-catalog
GET         /rule-library
PUT/DELETE  /rule-library/{id}
POST        /rule-definitions/validate
POST        /rule-sources
PUT         /data-sources/{id}/rule-version
POST        /data-sources/{id}/files?ruleSetVersionId={id}
GET         /jobs/{id}/rule-definition
```

Список наборов включает архивные; архивирование/восстановление — `PATCH` с `isArchived`. Отдельные GET деталей набора, GET списка grants, POST archive/restore пока не добавлены. Версии и списки постраничные; UI сейчас запрашивает первую страницу до 200 записей.

## Перенос исторических данных

Расширяющие EF migrations:

1. `20261106134434_UserOwnership` — Identity и nullable-владелец источника.
2. `20261106134858_RuleLibrary` — документы, наборы, версии, доступ и закладки.
3. `20261106135139_PinnedRuleExecution` — ссылки на правила, execution fingerprint и ValidRows.

Backfill назначает явно выбранного существующего пользователя только источникам без владельца; уже назначенные этому пользователю legacy-источники также переносятся. Данные других владельцев не присваиваются.

Каждый источник переносится в собственной транзакции под блокировкой. Текущая схема переносится даже без заданий. Исторические номера сохраняются, включая пропуски. Документ `legacy-customer-v1` хранит все поддерживаемые параметры схемы; номер ревизии не участвует в дедупликации содержимого.

Конфликт разных определений с одинаковым историческим номером откатывает этот источник; остальные бесконфликтные источники могут завершить перенос. Итоговый exit code ненулевой. Повторный запуск пропускает уже перенесённые источники.

Шесть PostgreSQL integration cases проверяют перенос, повторный запуск, сохранение прогресса завершённого задания, конфликт/rollback, дедупликацию и resume Processing-задания после падения Worker.

## Оставшаяся работа

- Финальное удаление legacy `SchemaJson`/`SchemaVersion` и обязательность ссылок: ещё не выполнены. Старые API создания Customer-источников и заданий пока поддерживаются; это требует отдельного переключения всех путей записи до contract migration.
- Для новых заданий с закреплённой версией JSON схемы пока также остаётся в legacy-колонке. Целевая экономия хранения полностью достигается после удаления этой копии.
- Полный визуальный редактор, просмотр/отзыв прямых grants в UI, страницы пагинации и браузерные E2E.
- XLSX и отчёты реализованы на этапе 9 (2026-11-09): XLSX-парсер через общий ParsedRow pipeline (первый лист, ZIP/лимиты, формулы без исполнения), потоковый CSV-отчёт ошибок с formula-injection защитой и Dashboard summary. Источники пользовательских правил принимают CSV и XLSX (`AcceptedFileFormat.All`).

Статистика проверок относится к конкретным прогонам; актуальные результаты фиксируются в журнале `plan.md`. Сводка не означает завершение всех пакетов расширения.
